1. STRUTTURA ARCHITETTURALE (SISTEMI A MEMORIA DISTRIBUITA)
-----------------------------------------------------------------------------------

A livello logico e fisico, un supercomputer e' un sistema a memoria distribuita
composto da migliaia di nodi indipendenti, ciascuno dotato del proprio spazio di
indirizzamento privato, collegati da una rete ad altissima velocita' e bassissima
latenza (Interconnect).

[SCHEMA 1: ARCHITETTURA GLOBALE A MEMORIA DISTRIBUITA]

  |   NODO / BLADE  |   |   NODO / BLADE  |                     |   NODO / BLADE  |
  |        0        |   |        1        |         ...         |       n-1       |
  +--------+--------+   +--------+--------+                     +--------+--------+
           |                     |                                       |

[DETTAGLIO COMPONENTI DEL NODO]

- CPU (Host)   : Processore multi-core general-purpose; ogni core ha ALU (calcolo),
                 Control Unit (decodifica/flusso) e L1 Cache privata, mentre L2/L3
                 sono condivise tra i core per ridurre la latenza verso la DRAM.
- GPU (Device) : Acceleratore massivamente parallelo suddiviso in Streaming
                 Multiprocessors (SM). Ogni SM condivide un'unica Control Unit e
                 una L1 Cache tra decine di semplici ALU (esecuzione SIMT), con una
                 L2 Cache globale e memoria dedicata ad altissima banda (HBM/DRAM).
                 Sistemi moderni ospitano fino a 4 o 8 GPU per singolo nodo.
- PCI-Express  : Bus di interconnessione interno ad alta banda che collega CPU,
                 GPU (incluso accesso diretto DMA alla DRAM della GPU) e NIC.
- NIC          : Network Interface Card; interfaccia il nodo con la rete globale.
                 Per evitare colli di bottiglia nelle comunicazioni multi-GPU, si
                 installa 1 NIC dedicata per ogni GPU (o 1 NIC ogni 2 GPU).


[SCHEMA 3: GERARCHIA DI SCALA (5 LIVELLI)]

1. CORE          --> Unita' base: ALU + unita' SIMD/FP + Load/Store + Cache L1
|
v
2. PROCESSOR     --> Chip singolo con decine di Core + Cache condivisa (L2/L3)
|
v
3. BLADE (NODO)  --> Scheda con piu' CPU + piu' GPU (4-8) + DRAM condivisa + NIC
|
v
4. RACK          --> Armadio con decine di Blade/Nodi + Switch di rete locale
|
v
5. FULL SYSTEM   --> Centinaia di Rack + Interconnect globale ad alta velocita'


[SCHEMA 4: PARADIGMI DI PROGRAMMAZIONE PER LIVELLO (APPROCCIO IBRIDO)]

- Core CPU      ---> Pthread / OpenMP  (Parallelismo a memoria condivisa sul nodo)
- Core GPU      ---> CUDA              (Parallelismo massivo sugli acceleratori)
- Tra i Nodi    ---> MPI               (Message Passing su memoria distribuita)


[TENDENZE ARCHITETTURALI NELLA CLASSIFICA TOP500]

- Acceleratori   : Solo una minoranza dei sistemi e' "CPUs Only" (es. LineShine,
                   Fugaku). La quasi totalita' della potenza di calcolo deriva da
                   nodi ibridi CPU+GPU dominati da NVIDIA (H100, H200, GH200, A100),
                   AMD (Instinct MI300A, MI250X) e Intel (Data Center GPU Max).
- Reti di rete   : Il Gigabit Ethernet e' relegato a sistemi minori o gestione.
                   I sistemi di vertice usano interconnessioni dedicate a bassa
                   latenza: NVIDIA InfiniBand, HPE Slingshot e reti
                   custom/proprietarie.

2. METRICHE DI PRESTAZIONE E BENCHMARK
-----------------------------------------------------------------------------------

A. UNITA' DI MISURA E PARAMETRI TOP500
- FLOP/s  : Floating-Point Operations per Second (operazioni in virgola mobile
            al secondo, tipicamente in doppia precisione FP64).
- Rpeak   : Picco teorico massimo dell'hardware, calcolato moltiplicando il
            numero totale di core, la frequenza di clock e le FLOP per ciclo.
- Rmax    : Prestazione sostenuta massima misurata eseguendo il benchmark HPL
            (High-Performance Linpack: risoluzione di un sistema lineare denso
            A*x = b tramite fattorizzazione LU).

B. ORDINI DI GRANDEZZA A CONFRONTO
- Singola CPU di fascia alta : ~10^12 FLOP/s (1 TeraFLOP/s)
- Supercomputer Exascale     : >10^18 FLOP/s (1 ExaFLOP/s = 1.000 PFlop/s)
- Rapporto di scala          : 6 ordini di grandezza (1.000.000x piu' potente)

C. BENCHMARK TOP500 (HPL) vs BENCHMARK REALISTICO (HPCG)
- HPL (TOP500) : Benchmark denso e fortemente "compute-bound" (satura le ALU
                 nascondendo i limiti di banda della memoria e della rete).
- HPCG         : High-Performance Conjugate Gradients; risolve sistemi sparsi
                 con pattern di accesso irregolari ai dati, risultando fortemente
                 "memory-bound" e "network-bound" (piu' fedele alle app reali).
- Divario      : Le prestazioni su HPCG sono circa 100 volte inferiori
                 rispetto a Rmax (calo di 2 ordini di grandezza).

     Esempio concreto (Sistema #1 LineShine):
- Rmax (HPL) : 2.198,40 PFlop/s  (~2,20 x 10^18 FLOP/s)
- HPCG       :    22,00 PFlop/s  (22.004,90 TFlop/s)  --> ~100x inferiore
